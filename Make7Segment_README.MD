# Make7Segment — Usage & Current Python Specification

This repository contains a single utility script to generate a 7-segment digit preview and simple CNC outline toolpaths:

- `Make7Segment.py` — canonical generator. It builds chamfered per-segment polygons, optionally performs a Shapely boolean union to merge seams (if `shapely` is installed or when `--use-shapely` is passed), and writes SVG, G-code, and optional WebP previews.

Outputs produced (per run):
- `<prefix>.svg` — vector preview (mm units)
- `<prefix>.gcode` — simple straight-line outline toolpaths (follow polygon vertices)
- `<prefix>.webp` — raster preview generated by Pillow (optional)

Dependencies
- Python 3
- Optional but recommended in a virtualenv: `pillow` (`pip install pillow`) for WebP export.
- Optional for boolean union: `shapely` (`pip install shapely`). When present `Make7Segment.py` can run the union pipeline; when absent the script emits per-segment polygons.

Key CLI options
- `--height` / `--width` : digit size in mm (defaults: 200, 95)
- `--stroke` : segment thickness in mm
- `--radius` : chamfer radius (used to compute chamfer polygon)
- `--bit` : cutter diameter for G-code comments (does not alter geometry)
- `--depth` / `--passdepth` / `--board-thickness` / `--cutting-paths` : control cut depth and pass splitting; when `--depth` omitted `--board-thickness` is used as depth.
- `--board-width` / `--board-height` : optional demo board dimensions (drawn in SVG and appended as a demo perimeter cut in G-code)
- `--show-board-dim` : embed board comments and use a single demo pass for G-code preview
- `--gap` / `--overlap` / `--hgap` : geometry tuning parameters for closing seams and shifting verticals
- `--vert-length` : adjust the length (mm) of vertical segments `F`,`B`,`E`,`C` by a signed delta (default `-10.0` in the script). Negative values shorten verticals; positive values lengthen them. The implementation recenters segments and clamps lengths to avoid overlaps.
- `--rotate` / `--no-rotate` : control a 90° rotation applied to output coordinates used for G-code (default: rotated). Use `--no-rotate` to keep the original orientation.
- `--spindle-speed` : if set, emits `M3 S<value>` at the start of the G-code (script default is `1000`).
- `--outprefix` : specify output filename prefix (default encodes H/W)
- `--render-source` : `poly` or `rect` (default `poly`) — controls how SVG and WebP are rendered:
	- `poly`: draw polygon vertices (matches the G-code toolpaths exactly)
	- `rect`: draw each segment as a rounded rectangle using the segment parameters
  
Additional shapely flags
- `--use-shapely` : force the boolean union step (requires `shapely`).
- `--no-shapely` : disable boolean union and emit per-segment polygons.

Rendering note
- The G-code is the authoritative output for CNC. To ensure the SVG and raster previews visually match the actual toolpaths, use `--render-source poly`. That causes both SVG and WebP to be drawn from the same polygon coordinates used to generate G-code toolpaths.

Examples
1) Canonical (polygon-rendered) outputs:
```bash
.venv/bin/python Make7Segment.py --height 200 --width 120 --board-width 150 --show-board-dim --render-source poly
```

2) Force union or per-segment behavior:
```bash
# force union (if shapely installed)
.venv/bin/python Make7Segment.py --use-shapely --render-source poly

# force per-segment (no union)
.venv/bin/python Make7Segment.py --no-shapely --render-source poly
```

3) Force rectangle/rounded-rect preview instead of polygon-based rendering:
```bash
.venv/bin/python Make7Segment.py --render-source rect
```

4) Adjust vertical length and rotation behavior (examples):
```bash
# shorten verticals by 1 mm and keep default rotated G-code
.venv/bin/python Make7Segment.py --vert-length -1

# increase verticals by 2 mm and disable rotation
.venv/bin/python Make7Segment.py --vert-length 2 --no-rotate
```

Notes & recommendations
- Run scripts with the project's virtualenv Python (`.venv/bin/python`) to ensure optional deps (`pillow`, `shapely`) are available.
- The G-code generator writes simple straight-line perimeter passes from polygon vertices — review generated G-code before running on hardware.
- Add these ignores to `.gitignore` to avoid committing generated outputs and macOS metadata:
	- `*.svg`, `*.gcode`, `*.webp`, `.DS_Store`, `.venv/`, `__pycache__/`

Shapely vs No-Shapely (what changes and why)
- `--use-shapely` enabled (or auto-detected when Shapely is installed): the script builds chamfered polygons for each segment and runs a boolean `unary_union` over them. The unioned geometry is then clipped to the board box and used as the authoritative outline for SVG, WebP and G-code. This removes seams and produces a single (or few) continuous outer contour(s) for cutting.
- `--no-shapely` (or when Shapely is not present): the script emits per-segment polygons (one polygon per A..G segment). The SVG/WebP/G-code reflect each segment individually — this can show tiny chamfer gaps or overlapping edges at segment joins.
- Practical effects:
	- Visuals: `use-shapely` usually looks cleaner (no diagonal gaps); `no-shapely` may show seams.
	- G-code: `use-shapely` produces simpler outer contours; `no-shapely` may produce multiple adjacent contours (which can cause overlapping cuts).
	- Precision: boolean union may slightly alter vertex positions (we clip to the board box to avoid tiny outward expansions). For very tight mechanical fits, inspect the resulting G-code.

New / updated CLI options
- `--use-shapely` : force the boolean union step (requires `shapely`) and use unioned polygons for outputs.
- `--no-shapely` : disable boolean union and emit per-segment polygons.
- `--render-source` : `poly` (default) or `rect`. `poly` draws polygons (matches the G-code toolpaths); `rect` draws per-segment rounded rectangles for reference visuals.

Default behavior
- If you omit both `--use-shapely` and `--no-shapely` the script auto-detects Shapely in the running Python interpreter and uses it when available. This means in your `.venv` (if Shapely installed) the script will use union by default; in a bare `python3` it will fall back to per-segment mode.

Quick compare commands
```bash
# force per-segment (no union)
.venv/bin/python Make7Segment.py --use-shapely # force union (if available)
.venv/bin/python Make7Segment.py --no-shapely   # force per-segment polygons

# explicitly match visuals to G-code
.venv/bin/python Make7Segment.py --render-source poly --use-shapely
.venv/bin/python Make7Segment.py --render-source poly --no-shapely
```
